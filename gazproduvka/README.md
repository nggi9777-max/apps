# ГазПродувка 2.2 — настольная программа с прямым подключением к PostgreSQL

ГазПродувка.exe работает по принципу Power BI Desktop: программа сама подключается
к серверу PostgreSQL по TCP через встроенный драйвер на Rust. Шлюз Node.js,
промежуточные серверы и дополнительные службы не нужны.

```
ГазПродувка.exe ── драйвер PostgreSQL (Rust: tokio-postgres + TLS SChannel) ── сервер PostgreSQL
   интерфейс (WebView2)  ⇄  команды Tauri  ⇄  backend на Rust
```

## Состав проекта

| Папка / файл | Назначение |
|---|---|
| `desktop/src-tauri/src/lib.rs` | Backend на Rust: подключения, Navigator, просмотр, загрузка, хранилище паролей Windows |
| `desktop/src-tauri/tauri.conf.json`, `Cargo.toml` | Настройки программы и сборки (Tauri 2, установщик NSIS) |
| `desktop/dist/index.html` | Интерфейс (тот же, что `dist/GazProduvka.html`, собирается `build.py`) |
| `src/*.js` | Исходный код интерфейса и расчётного ядра. Новое: `views3.js` (Получить данные, Navigator, преобразование), `sources.js` (прямой транспорт) |
| `build.bat` | Сборка .exe на Windows одной командой |
| `build-mac.sh` | Сборка .dmg на macOS одной командой |
| `.github/workflows/build-windows.yml` | Сборка .exe и .dmg в GitHub Actions (Windows и macOS) |
| `desktop/test/shim.js`, `tests/` | Тестовый двойник backend и автотесты на реальном PostgreSQL |
| `gateway/` | Старый шлюз Node.js — только режим совместимости для HTML в обычном браузере, программе .exe не нужен |

## Сборка ГазПродувка.exe

**Вариант 1 — на компьютере с Windows 10/11:**
1. Установить Rust: `winget install Rustlang.Rustup`.
2. Установить Visual Studio Build Tools, компонент «Разработка классических приложений на C++».
3. Запустить `build.bat`. Результат: `GazProduvka.exe` в корне проекта и установщик в
   `desktop\src-tauri\target\release\bundle\nsis\`.

**macOS (MacBook, Apple Silicon или Intel):** в Терминале выполнить `./build-mac.sh` — скрипт сам
установит Rust и соберёт `GazProduvka.dmg` (нужны инструменты Apple: `xcode-select --install`).
Программа не подписана сертификатом Apple, поэтому при первом запуске: правый клик → «Открыть»
(или `xattr -dr com.apple.quarantine /Applications/GazProduvka.app`).

**GitHub Actions (оба установщика сразу):** загрузить проект в репозиторий, открыть Actions →
«Сборка ГазПродувки» → Run workflow; через ~15 мин готовы артефакты `GazProduvka-windows` (.exe)
и `GazProduvka-macos` (.dmg, универсальный для Apple Silicon и Intel).

Для работы программы нужна среда WebView2 — она уже есть в Windows 10/11; установщик
при необходимости ставит её сам. Интерфейс встроен в .exe, внешних файлов нет.

## Порядок работы (как в Power BI)

1. **Получить данные** → 2. **База данных PostgreSQL** → 3. параметры: сервер/IP, порт (5432),
база, метод авторизации, пользователь, пароль, SSL Mode, тайм-аут, application_name, часовой пояс,
options → 4. **Проверить подключение** → 5. **Подключиться** → 6. **Navigator**: базы данных
сервера, схемы, таблицы и представления с поиском → 7. выбор нескольких объектов флажками →
8. просмотр первых 200 строк и выбор столбцов → 9. **Преобразовать данные**: связи (JOIN) со
справочниками, сопоставление с полями ГазПродувки, единицы давления, диапазон дат, фильтры строк,
просмотр результата и списка скважин → 10. **Загрузить**.

Данные попадают в существующее расчётное ядро без изменений: иерархия месторождение → скважина,
Pwh/Pline, циклы, прогнозы, анимация, сводка фонда, отчёты. Режимы OFFLINE / ONLINE /
объединённые данные, локальный кэш и инкрементальное обновление сохранены.

## Безопасность

- Пароль вводится один раз и хранится в **Диспетчере учётных данных Windows**; в файл настроек
  и обратно в интерфейс не попадает. Можно не сохранять пароль — тогда он живёт только до закрытия программы.
- Сессия переводится в режим **только чтения** (`default_transaction_read_only = on`), тайм-аут запроса 120 с.
- Имена схем, таблиц и столбцов проверяются по системным каталогам; значения фильтров, дат и
  курсоров передаются только **параметрами запроса**.
- TLS: `disable`, `prefer`, `require`, `verify-ca`, `verify-full` (проверка сертификата средствами Windows).
- Объём ограничен: просмотр — 200 строк, страница загрузки — до 50 000 строк.

## Что нужно на стороне сервера PostgreSQL

Программа не обходит сетевые ограничения. Администратор БД должен:

```conf
# postgresql.conf
listen_addresses = '*'            # или конкретный адрес сервера
ssl = on                          # рекомендуется
# pg_hba.conf — доступ из сети диспетчерской, только по TLS
hostssl  scada_db  gp_reader  10.0.0.0/16  scram-sha-256
```

```sql
CREATE ROLE gp_reader LOGIN PASSWORD '…';
GRANT CONNECT ON DATABASE scada_db TO gp_reader;
GRANT USAGE ON SCHEMA scada TO gp_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA scada TO gp_reader;
```

Порт 5432 (или другой) должен быть открыт в сетевом экране между рабочим местом и сервером.

## Переход со шлюза

Настройки и загруженные данные сохраняются. В программе .exe шлюз не используется: адрес и токен
шлюза из интерфейса убраны. Подключения нужно один раз создать заново через «Получить данные»
(пароли шлюза были зашифрованы ключом шлюза и в программу не переносятся — так и должно быть).
Ранее полученные из PostgreSQL измерения остаются в локальной базе.

## Проверка (выполнена на PostgreSQL 16)

`node tests/t_native.js` — 40 проверок: подключение с TLS и без, `require`, неверный пароль,
отсутствующая база, закрытый порт, две базы на одном сервере, Navigator по системным каталогам,
права SELECT, просмотр, фильтры, попытки SQL-инъекций (имя таблицы, столбца, значение, часовой
пояс, сопоставление), запрет записи, JOIN со справочниками, постраничная и инкрементальная загрузка
(новые и изменённые записи), таблица 1 млн строк, потеря соединения и автоматическое
переподключение, сохранение и восстановление настроек и паролей.
`tests/t_ui_native.js` — весь путь в интерфейсе; `tests/t_offline.js` — OFFLINE Excel/7z без
backend; `tests/t_equiv.js` — одинаковые результаты расчёта по данным из 7z и из PostgreSQL.

Тесты выполняют те же команды и те же SQL-тексты, что backend на Rust, через тестовый двойник
`desktop/test/shim.js`. Компиляция Rust выполняется при сборке .exe (build.bat или GitHub Actions).
